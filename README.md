# 修复视频时间轴

一个 Windows 图形小工具，用于修复视频时间轴异常：起始时间偏移、时间戳缺失或错乱、播放器拖动进度条错位等。修复采用 stream copy，不重新编码，速度快、画质无损。

程序是单个原生窗口程序（.NET Framework 4.8，Win10 1903 / Win11 及以上系统自带运行时，**免安装、双击即用**），无需命令行。

## 文件说明

| 文件 / 目录            | 作用                                            |
| -------------------- | --------------------------------------------- |
| `修复视频时间轴.exe`       | 主程序，双击打开图形界面                                  |
| `tools\ffmpeg\`      | FFmpeg 所在位置，缺失时自动下载到这里                         |
| `temp\`              | 覆盖模式运行时的临时文件目录，运行结束自动清理                        |
| `log\`               | 运行日志，每次修复生成一个 `.log` 文件                        |
| `src\`               | C# 源码（WinForms / net48），一般用户无需关心               |

## 使用方法

双击 `修复视频时间轴.exe` 打开窗口，然后任选一种方式添加视频：

- 点「选择视频文件...」一次多选；或点「选择文件夹...」批量选中整个目录；
- 直接把视频文件或文件夹**拖到窗口里**。

接着：

1. 需要连子目录一起处理时，勾选「包含子文件夹」；勾选后不会实时统计数量（子目录可能很多、实时遍历会卡界面），改为在点击「开始修复」后于后台逐个遍历并统计；
2. 在「② 输出」选择修复结果的存放方式（见下方[输出规则](#输出规则)）；
3. 不希望覆盖已有结果时，勾选「输出已存在时跳过」（默认覆盖）；
4. 点「开始修复」，在预览框确认文件清单与目标路径后开跑；
5. 进度条实时显示总进度与当前文件（文字直接画在进度条内），下方日志区同步滚动显示每个文件的开始与结果，并**按颜色区分**：任务开始（蓝）、完成（绿）、降级完成（橙）、失败（红）、跳过（灰）、中断（紫）、程序级错误（红底白字）；日志区支持横向与纵向滚动，长文件名不会自动换行打断版面；
6. 中途可点「停止」中断（被中断的文件不计入失败）。

**受众区分**：窗口里的内容面向日常使用，只给「谁成功了 / 谁失败了 / 为什么失败」的概要；`log\` 下的日志文件面向排查问题，记录全部细节（含 FFmpeg 原始输出与失败文件末尾若干行）。

- **执行过程与结果都在窗口日志区**：每个文件的开始与结果、以及**队列结束的汇总**（成功 / 失败 / 跳过条数）都会写进执行过程展示框，不需要依赖状态栏那行小字；
- **弹出窗口一律只给汇总**：确认框与结束提示只显示「处理条数 + 输出方式 + 输出位置」，**不罗列文件清单**（列表太长会把下方的警告文字挤出视野），完整清单请查看日志文件；
- 失败时窗口底部会列出**按原因分组的失败数量**，详细到每个文件的清单只在日志里。

**空间预检**：每个文件开始前会检查目标磁盘剩余空间是否够放修复结果（额外留出安全余量），不够的直接跳过并在日志中标明，**不计入失败**。覆盖模式下按程序所在盘检查（临时文件写在那里），其余模式按输出路径所在盘检查。

支持的容器扩展名：`.mp4 .mkv .mov .avi .flv .wmv .m4v .ts .mts .m2ts .mpg .mpeg .rmvb .rm .webm .3gp .vob .asf`。

## 输出规则

在「② 输出」里**三选一**。前两种方式不会改动源文件；第三种为破坏性操作。

**方式一：输出到子目录 genpts（默认、推荐）**
在每个源视频所在目录下新建 `genpts` 子目录，输出文件名与源文件相同。

```
X:\clips\a.mp4          ->  X:\clips\genpts\a.mp4
X:\clips\sub\b.mkv      ->  X:\clips\sub\genpts\b.mkv
```

**方式二：与原文件在同一目录**
输出到源文件所在的同一文件夹，主文件名后追加 `_genpts`。

```
X:\clips\a.mp4          ->  X:\clips\a_genpts.mp4
X:\clips\sub\b.mkv      ->  X:\clips\sub\b_genpts.mkv
```

**方式三：覆盖原文件（直接替换，不可恢复）**
修复成功后用结果**直接替换原文件**，文件名与位置保持不变。

```
X:\clips\a.mp4          ->  X:\clips\a.mp4（内容已被修复结果替换，原文件不保留）
```

- 为保证安全，该方式不会让 FFmpeg 原地写文件：临时文件统一写到程序运行目录下的 `temp\` 目录，文件名为**源文件完整路径的 MD5**（32 位十六进制，保留原扩展名以保证容器一致），例如源 `X:\clips\a.mp4` 的临时文件形如 `temp\3a870ebe58fe937efc9baca603195ad4.mp4`；**确认修复成功后才替换**原文件；替换优先用同卷原子操作，失败时自动退回「先备份再移动、移动失败则还原备份」，尽量保证原文件不丢；
- **只读属性**：源文件若是只读，程序会在替换前临时去掉只读位，替换成功后**自动还原为只读**；源文件本来不是只读的，程序**不会**给它加上只读；
- 每个文件修复完成后只删除它自己的临时文件；等队列里的文件全部处理完，再一次性删除 `temp\` 整个目录；下次开始时还会再清扫一遍上次异常退出可能残留的临时文件（只删除带本程序临时标记的文件）；
- 修复失败、或你点了「停止」时，只删除临时文件，**原文件保持不动**；万一「修复成功但替换失败」，原文件同样不受影响，修复结果临时文件会保留在 `temp\` 下供你手动处理；
- 该选项会弹出**两次**危险操作确认，确认后才执行；重要视频建议先自行备份；此模式下「输出已存在时跳过」不适用。

通用说明：

- 方式一、二的源文件都保持原样，可放心反复运行；
- 扫描文件夹时会自动跳过 `genpts` 目录内的文件、主名以 `_genpts` 结尾的成品、程序运行目录下的整个 `temp\` 目录，以及源目录中残留的临时文件（含本程序生成的 MD5 命名临时文件与旧版 `.__genpts_tmp_` 标记文件），因此反复运行不会把已生成的结果当成新输入（不会套娃）；若你**手动指定**某个成品文件，则仍会照单处理；
- 方式一、二下输出已存在时默认覆盖，勾选「输出已存在时跳过」则跳过。

## 修复策略：增强 + 自动降级

|           | 基础模式                      | 增强模式                                                                             |
| --------- | ------------------------- | -------------------------------------------------------------------------------- |
| FFmpeg 参数 | `-c copy -fflags +genpts` | 基础参数 + `-avoid_negative_ts make_zero -reset_timestamps 1 -map 0 -ignore_unknown` |
| 时间戳       | 生成缺失的 PTS                 | 额外把所有时间戳归零，各条流从 0 重新计数                                                           |
| 流         | 只保留最佳的一条视频 + 一条音频         | 保留源文件里的**全部**流（多音轨、内嵌字幕等）                                                        |
| 失败风险      | 低                         | 略高（部分容器不支持某些流类型）                                                                 |

**固定流程**：每个文件先用增强参数处理；只有当它失败时，才自动改用基础参数重做同一个文件。这样既拿到保留全部流的修复效果，又不会因为个别不兼容而整体失败。界面与日志里会明确标出哪些文件是「增强失败后降级完成」的。单纯的起点偏移或 PTS 缺失，两种参数的结果通常一致。

## 运行日志

每次点「开始修复」都会在程序所在目录的 `log\` 下生成一个日志，命名为 `yyyy-MM-dd_HH-mm-ss.log`（同一秒重复会自动加序号）。

日志逐条记录：待处理清单、每个文件的输入/输出路径、所用模式、FFmpeg 退出码与耗时、是否降级、失败原因分类、按原因分组的失败清单与最终汇总；FFmpeg 自身的完整错误输出、以及失败文件末尾若干行也会收录，排查失败原因时直接看日志即可。

失败原因会尽量细分为：磁盘空间不足、源文件损坏或数据无效、权限不足、源文件不存在或路径无效、路径过长、编码格式不支持、缺少组件（解码器 / 滤镜 / 库）、文件被占用、参数无效、FFmpeg 内部错误、被中断、以及其它原因。判定优先看 FFmpeg 的错误文字，其次才参考退出码（退出码单独并不可靠，例如「文件不存在」在绝对路径下可能返回非预期值）。

```
X:\...\log\2026-10-10_15-47-36.log
```

## FFmpeg 的获取

程序**只在自身所在目录查找** FFmpeg（`修复视频时间轴.exe` 同级的 `ffmpeg.exe`，或 `tools\ffmpeg\ffmpeg.exe`），找不到时在首次修复时自动联网下载（约 85 ~ 115 MB），也可随时点窗口左下角「检测 / 下载 FFmpeg」手动获取。

下载来源按优先级：先读 `ffmpeg.org` 官方下载页确认 Windows 构建入口，再依次尝试 `gyan.dev`、GitHub `BtbN/FFmpeg-Builds`；采用 8 线程分段下载（每段独立临时文件，校验后合并）。想换版本时删掉 `tools\ffmpeg\` 目录后重新下载即可。

## 从源码构建（可选）

源码在 `src\`，面向 .NET Framework 4.8 的 WinForms 工程。安装 .NET SDK 后：

```
cd src
dotnet build -c Release
```

产物位于 `src\bin\Release\net48\修复视频时间轴.exe`，可单文件拷出使用。
